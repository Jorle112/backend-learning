## 为什么 choice 用 String 而不是 int？

读选项用 `sc.nextLine()` 得到 String，判断时才 `choice.equals("1")`。

如果用 `int choice = sc.nextInt()`，**换行符会残留在缓冲区**，导致下一次 `nextLine()` 读到空串 → 查找、删除全失效（目标永远是空字符串）。

```java
// 推荐：读一行，无残留，安全
String choice = sc.nextLine();
if (choice.equals("1")) { ... }

// 不推荐：nextInt 读完，回车还留在缓冲区，后面 nextLine 会读到空
int choice = sc.nextInt();
if (choice == 1) { ... }
```

小结：
- `nextLine()` + String：无残留坑，但判定要写 equals
- `nextInt()` + int：类型直观，但要防换行残留（需补一次 `nextLine()` 吃掉回车）

## 删除为什么要写 songs.get(i)？

增强 for 拿不到元素的下标（位置编号），而 `remove(下标)` 是按位置删，所以必须用普通 for + `i` 记录位置。

```java
int remove = -1;                           // 哨兵：-1 = 没找到
for(int i = 0; i < songs.size(); i++){
    if(songs.get(i).getTitle().equals(target)){   // get(i) = 按下标取元素
        remove = i;
        break;                              // 删除只要一首，找到就停
    }
}
if(remove == -1){
    System.out.println("未找到歌曲");
}
else{
    songs.remove(remove);
    System.out.println("已删除");
}
```

对比：
- 查找只看内容 → 增强 for `for(Song song : songs)` 够用
- 删除要位置 → 必须普通 for + `songs.get(i)` 拿下标

## 为什么 songs.remove(remove) 一行就能删？

`songs.remove(int)` 是 ArrayList 自带的方法，按**下标**删除，内部自动把后面元素往前挪，所以删完顺序不乱、不留空位。

注意分离两个概念：
- `remove` 变量：存的不是歌，是歌的**下标**
- `remove(int)` 方法：ArrayList 的删除方法，按下标删除

## 收藏筛选（菜单项 4）

```java
int favCount = 0;
for(Song song : songs){
    if(song.isFavorite()){      // 只挑收藏的
        song.b();
        favCount++;
    }
}
System.out.println("收藏歌曲数" + favCount);
```

配套 Song 类要有的成员：`boolean favorite` 字段 + `isFavorite()` + `setFavorite()`。boolean 字段 getter 用 `is` 前缀，不写 `get`。

## equals 记忆卡

- `==` 比**地址**（new 出来的两个 String 一定为 false）
- `equals` 比**内容**（String 重写了 equals）
- `"hello".equals(1)` 编译直接报错——类型不匹配，不是相等性判断
